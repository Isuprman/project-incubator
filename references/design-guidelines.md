# Design Guidelines — Built-in Fallback

内置通用设计规则。当环境中没有设计类 skill（design-taste / ui-ux-pro-max 等）时，
实现与设计审查按本文件执行。这些是最硬、最不会出错的规则——宁可保守也不要"AI 味"。

> 若环境存在更强的设计 skill（design-taste、ui-ux-pro-max、game-ui-design 等），
> 按页面类型路由：系统/工具页 → ui-ux-pro-max；营销/产品页 → design-taste；游戏 UI → game-ui-design。
> 本文件始终作为兜底与审查基准。

## 铁律（必须遵守）

1. **无背景块**：装饰性面板不要用背景色块/卡片堆叠。纯排版靠间距、字号、对齐建立层级。按钮/输入框等交互控件可以有边框和底色。
2. **布局**：居中对称、主次分明。状态徽章不挤标题。全屏分散（左信息右操作），不挤中央单列。
3. **间距**：统一 scale（4px / 8px 基数）。同层级间距一致，层级间用大间距区分节奏。
4. **字号层级**：h1→h2→h3→body 对比明显（≥1.25 倍）。正文行高 1.5–1.6，标题 1.1–1.2。正文行长 ≤ 75ch。
5. **颜色**：最多一个强调色，全页锁定。正文对比度 ≥4.5:1。不用纯 #000/#fff（用 off-black / off-white）。灰字配浅底是最大通病——往墨色方向加浓度。
6. **字体**：≤3 个字体族（display + body + 可选 mono）。避免 Inter 和 AI 常用衬线（Fraunces 等）作默认。
7. **状态齐全**：交互元素设计全部状态——default / hover / focus / active / disabled / loading / error / success。focus 必须有可见环（永不 outline: none 裸删）。
8. **表单**：标签在输入框上方（不用 placeholder 当标签）。错误提示在输入框下方，连 aria-describedby。触控目标 ≥44px。
9. **动效克制**：只动 transform/opacity，<300ms，ease-out。必须有 prefers-reduced-motion 降级。不为"炫"而动。
10. **文案**：按钮 = 动词 + 宾语（"保存更改" 而非 "确定"）。全文不用 em dash（—）——最大的 AI 特征。无营销空词（赋能/极致/丝滑）。

## 禁止清单（AI 味重灾区）

- 渐变文字、玻璃拟态默认、侧边竖条装饰、hero 指标模板、千篇一律的卡片网格
- 每节都放 eyebrow 小标签、幽灵卡片（边框+阴影）、过度圆角（卡片 ≤12–16px）
- 假的截图占位（fake div screenshots）、随手画的 SVG
- z-index 用 999/9999（要有语义层级 scale）

## 页面类型速查

| 页面类型 | 布局倾向 | 注意 |
|---|---|---|
| 系统/工具页（表单、表格、仪表盘） | 左信息右操作、密度适中 | 标签在上、空/错/加载状态齐全 |
| 营销/产品页 | 大 hero + 清晰 CTA | 首屏 hero ≤2 行标题、CTA 不滚动可见 |
| 列表/详情 | 列表留白均匀、详情分层 | 状态徽章不挤标题 |
| 空状态/错误页 | 居中、一句话 + 一个动作 | 不要只写"出错了" |

## 审查速查（设计轴）

对每个界面检查：

- [ ] 有无装饰性背景块（违反铁律 1）
- [ ] 间距是否统一 scale、对齐是否一致
- [ ] 字号层级是否分明（≥1.25 倍）
- [ ] 强调色是否唯一且全页一致
- [ ] 8 状态是否齐全（尤其空/错/加载）
- [ ] 表单标签在上、错误在下
- [ ] 无 AI 味元素（对照禁止清单）
- [ ] 布局是否居中对称、主次分明、状态徽章不挤标题
